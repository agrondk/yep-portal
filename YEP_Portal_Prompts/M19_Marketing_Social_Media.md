# M19 — Marketing campaigns & social media (with ML triggers and AI-generated campaign drafts)

**Depends on:** M01, M02, M06, M09, M10, M12 (M17 and M18 for smart triggers and AI drafts). **Attach with:** `01_MASTER_CONTEXT.md`, `PROGRESS.md`.
**When:** basic campaigns, tracking links and the content calendar can ship in Release 2; smart triggers and AI generation in Release 4.

## Goal
Run all of YEP's marketing from the portal and connect it to real results:
1. Plan campaigns, create posts and emails, schedule and publish to Facebook and Instagram, and track spend.
2. Measure what each campaign brings: inquiries, trial classes, applications, enrollments, revenue, cost per enrollment.
3. **Automatically detect when marketing is needed** — falling enrollment in a program, empty seats before a start date,
   low conversion, or a program whose costs exceed its income — and propose a ready-to-review campaign draft generated by AI.

The system **suggests and drafts**; a person approves every campaign, post, budget and discount before anything is published or spent.

## Scope
**In:** campaigns, audiences, channels (Facebook, Instagram, email via M10, website banner, printed flyers/QR), content calendar,
post drafts and variants (sq/en), media library with photo-consent checks, social account connection, scheduled publishing,
post and campaign metrics, ad spend recording, tracking links (UTM) and QR codes, promo codes linked to M06 discounts,
attribution of inquiries/applications/enrollments to campaigns, ROI reporting, **trigger rules + ML signals → campaign suggestions**,
**AI campaign generation** (via M18), marketing dashboard.
**Out:** buying ads automatically, automated audience targeting with personal data, publishing without approval, AI-generated images of children.

## Integrations
- **Meta Graph API** (Facebook Page posts, Instagram Business posts, post insights) through a `SocialProvider` Protocol:
  `MetaProvider` + `ManualProvider` (export text/images for manual posting and manual metric entry). Meta access requires an app
  with approved permissions (app review); until approved, use `ManualProvider` — never report a post as published unless the API confirmed it.
- Tokens stored encrypted; account connection only by owner_admin or marketing_coordinator.
- Optional later adapters: TikTok, Google Business Profile, Google Ads/Meta Ads spend import (CSV import supported from day one).

## New role
`marketing_coordinator` (invitation-only): campaigns, content, media library, social accounts, suggestions, marketing reports.
Sees aggregated enrollment/finance figures per program needed for marketing — not household data, not individual invoices.

## Triggers — when the system proposes action
Run daily (Celery Beat). Each rule has thresholds, cooldown, and writes a `campaign_suggestion` with the evidence numbers shown to the user.

| Rule | Signal (from) | Default condition (configurable) | Typical suggestion |
| --- | --- | --- | --- |
| `enrollment_drop` | M12 reporting | Active enrollments in a program down ≥ 15% vs same period last year or vs previous term | Enrollment campaign for that program |
| `below_forecast` | M17 demand forecast | Applications for next term < 70% of forecast lower bound, N weeks before start | Targeted campaign + trial classes |
| `unfilled_seats` | M02/M03 capacity | Offering < 60% filled, 21 days before start | Last-seats campaign, promo code proposal |
| `low_conversion` | M01/M02 funnel | Inquiry → enrollment conversion < X% over 60 days | Follow-up email sequence, trial-class push |
| `trial_no_conversion` | M01 trials | Trial attendees not enrolled after 14 days | Personal follow-up campaign (consented contacts only) |
| `renewal_risk` | M17 dropout risk | ≥ N enrolled children high-risk in a program near term end | Renewal/progression campaign (e.g. next-level program) |
| `program_loss` | M06 + M09 + M07 by program | Program costs (instructor pay, materials, rent share, marketing) > course income for 2 consecutive months | **Review**: campaign to fill groups *and/or* price review, merge small groups, cost review — shown side by side |
| `marketing_roi_low` | M19 attribution | Running campaign cost per enrollment > target | Pause / change channel suggestion |
| `seasonal` | calendar | Pre-season windows (e.g. September start, winter/summer camps) | Seasonal campaign template |
| `school_pipeline_gap` | M05 | Fewer than N active proposals for next school year by a set date | School outreach campaign |

The `program_loss` rule uses the program profitability view (income by payment or invoice date — labelled; costs allocated through ledger dimensions)
and must state its date basis and which costs are included. It never decides a price change — it only proposes options.

## AI campaign generation (uses M18 provider and privacy rules)
When a suggestion is accepted (or a user clicks "Generate campaign with AI"), the AI receives **only aggregated, non-personal context**:
program description and objectives, age range, location, dates, seats left, price and any approved promo, the trigger evidence numbers,
past campaign results (aggregated), brand voice notes and YEP facts from master §1. It returns a **draft campaign**:
- goal, target audience description, key message, channels and timing, suggested budget split (within a configured maximum),
- 3–5 Facebook/Instagram posts (sq + en) with hashtags and call to action, 1 email to consented parents, flyer text, reel/story script,
- KPI targets (inquiries, trials, enrollments) based on past conversion rates, clearly marked as estimates,
- optional promo code proposal (requires finance approval before activation).
Rules for AI content: no invented testimonials, results, awards or prices; no claims that LEGO® sponsors/endorses YEP; no use of children's names;
images chosen only from the media library with `consent_ok = true` (AI may suggest which asset fits; it never generates images of children).

## Rules
- Workflow: suggested → draft → pending_approval → approved → running → completed. Publishing, spending and promo codes require approval
  (owner_admin, or marketing_coordinator within budget limits; promo codes also finance_officer).
- Email campaigns go only to users with marketing consent (M10); essential messages are never used for marketing.
- A media asset showing a child can be used only while that child's photo/video consent is valid; consent withdrawal automatically flags affected content and blocks scheduled posts.
- Scheduled posts are published by a Celery task; failures are visible and retried a limited number of times; no duplicate posts on retry.
- Attribution: tracking links and promo codes captured on inquiry/application forms (M01/M02 store `utm_*` and `promo_code`); "How did you hear about us?" as self-reported fallback. Reports show attribution method.
- Ad spend recorded once; if linked to a supplier bill (M09), the bill is the cost of record.
- ROI metrics (registered in M12 `metric_definition`): cost per inquiry, cost per trial, cost per enrollment, attributed revenue (first 3 months, payment basis), return on spend.
- Suggestions have cooldowns so the same signal does not create repeated suggestions; dismissed suggestions require a reason.

## Acceptance tests
- Bricks Challenge enrollments drop 20% vs last year → one suggestion with evidence is created; rerunning the job within cooldown creates no duplicate.
- A program with costs > income for 2 months produces a `program_loss` suggestion listing campaign, price review and cost options, with date basis stated.
- Accepting a suggestion and generating with AI produces a draft campaign with sq/en posts; the AI payload contains no personal data (TestProvider capture); prices in posts equal catalog/approved promo prices.
- A post using a photo of a child whose consent was withdrawn is blocked from publishing.
- Nothing is published, spent or activated without approval; Meta publishing failure leaves the post `failed`, never `published`.
- An inquiry arriving through a tracking link and an enrollment using the promo code are attributed to the campaign; cost per enrollment reconciles with recorded spend.
- Email campaign recipients are only users with marketing consent.
